# ContextMesh · WorkBuddy 项目决定交接

**上午改的需求，下午同事的 AI 能用对吗？** 把已确认的变更写成一条小记录。另一位成员在自己的 WorkBuddy 会话中写验收用例时，可以查到哪条决定对谁生效，并引用原文。

v0.1 是一个纯文本 Skill，复用 WorkBuddy 的文件工具。无需自建服务器、数据库或申请模型 API Key。跨设备试用需要两人都能访问同一份项目文件，例如已有的共享盘或已同步的项目目录。

## 一分钟看懂

| 提问 | 应得到的结果 | 依据 |
|---|---|---|
| 企业试点如何登录？ | 邮箱验证码 | D-02.md |
| 公众注册如何登录？ | 短信验证码 | D-01.md |

两条决定都有效，只在企业试点这个范围发生了替代。

## 在自己的 WorkBuddy 中试用

1. 下载 [Skill 安装包](dist/contextmesh-decisions.zip)。在 WorkBuddy 的「专家·技能·连接器 → 技能 → 添加技能」中选择上传本地技能包。使用支持本地文件工具的任务模式。
2. 下载本仓库并解压，将 [examples/login](examples/login) 选为 WorkBuddy 的工作目录。安装包只包含技能说明，样例决定在项目目录里。
3. 新开会话发送：**使用“项目决定交接”，读取项目决定，为企业试点和公众注册分别写一条登录验收用例，并注明依据文件。** 用上表核对。不要把预期答案粘进提示词。

## 让另一位成员接手

两位成员各自安装 Skill，并打开同一个已同步的共享项目目录。A 说“把这次变更写成项目决定”，给出结论、适用范围、生效日期和依据，预览后确认。B 等文件同步后，在独立会话中提出相关任务并要求使用项目决定。先验证 B 能读对与引用，再尝试普通提问，观察客户端是否会自然触发技能。文件访问权限沿用现有共享目录。

## 试点边界

当前实现依赖助手执行技能指令；自动触发和答案正确率要用真实客户端验证。项目正收集脱敏案例：如果遇到局部变更误用，欢迎在 Issue 里提供最小示例、期望答案和实际引用。
